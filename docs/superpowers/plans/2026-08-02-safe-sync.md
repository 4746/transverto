# Safe Label Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `ctv label:sync` with a plan-first, filterable, optionally translated, transaction-safe synchronization command.

**Architecture:** A repository loads validated dictionaries and exact byte snapshots, a pure planner creates frozen ordered actions, the existing translation batch resolves only translation actions, and an executor applies accepted actions plus one generated enum through one guarded file transaction. The command owns only flag validation, orchestration, confirmation, rendering, and exit codes.

**Tech Stack:** Node.js 24.15+, TypeScript 6 ESM, oclif 4, Inquirer prompts, existing translation/cache/fallback/batch services, Node filesystem APIs.

## Global Constraints

- Runtime remains `node >=24.15` with Node 24 types and ESM imports ending in `.js`.
- Do not add tests or change test infrastructure.
- JSON output is stable and contains no ANSI.
- `--dry-run` performs no network calls and no writes.
- Non-TTY mutation requires `--write`; TTY preview may be confirmed interactively.
- JSON dictionaries are written atomically through temporary files in the same directory.
- Do not add compatibility aliases for removed `--noReport` or `--silent` flags.
- Do not implement task 11 bulk mutations, CSV import, or remote TMS behavior.

### Task 2: Sync domain model and snapshot repository

**Files:**

**Interfaces:**
- Produces: `TSyncActionType = 'add' | 'remove' | 'keep' | 'translate' | 'skip' | 'conflict'`.
- Produces: `TSyncExtraPolicy = 'keep' | 'report' | 'remove'`.
- Produces: `ISyncProjectSnapshot`, `ISyncDictionarySnapshot`, `ISyncAction`, `ISyncPlan`, `ISyncExecutionOutcome`, `ISyncReport`, and per-language summary types.
- Produces: `SyncRepository.load(config: IConfig, options: ISyncLoadOptions): Promise<ISyncProjectSnapshot>`.

- [ ] **Step 1: Define stable sync entities**

Define readonly records whose action identity is `(language, key)`. Each action has `type`, `language`, `key`, `reason`, `sourceValue`, and `targetValue`; values are `string | null`. The plan includes source, ordered targets, filters, extra policy, autoTranslate, and actions. Execution outcomes hold batch output (or null), written files, and confirmation state without modifying actions.

```ts
export interface ISyncAction {
  readonly key: string
  readonly language: string
  readonly reason: TSyncActionReason
  readonly sourceValue: null | string
  readonly targetValue: null | string
  readonly type: TSyncActionType
}

export interface ISyncPlan {
  readonly actions: readonly ISyncAction[]
  readonly autoTranslate: boolean
  readonly extra: TSyncExtraPolicy
  readonly filters: Readonly<IKeyFilters>
  readonly source: string
  readonly targets: readonly string[]
}
```

- [ ] **Step 2: Load and validate exact snapshots**

Implement repository loading for the selected source, targets, and types file. Validate configured language codes, source/target membership, duplicates, relative paths, dictionary existence/root shape, and string-only leaves. Retain exact `Buffer` content and parsed structured objects. Preserve configuration order for selected targets even if `--to` order differs.

```ts
export interface ISyncLoadOptions {
  cwd?: string

export class SyncRepository {
  static load(config: IConfig, options?: ISyncLoadOptions): Promise<ISyncProjectSnapshot>
```


### Task 3: Immutable synchronization planner

**Files:**
- Create: `src/shared/sync-planner.ts`

**Interfaces:**
- Consumes: `ISyncProjectSnapshot`, `IKeyFilters`, `TSyncExtraPolicy`.
- Produces: `SyncPlanner.create(snapshot: ISyncProjectSnapshot, options: ISyncPlanOptions): ISyncPlan`.
- Produces: `syncTranslationRequests(plan: ISyncPlan): ITranslationRequestPlan[]`.

- [ ] **Step 1: Normalize planning options**

Validate extra policy against `['keep', 'report', 'remove']`, normalize filters with Task 1, and store the repository-resolved source and targets. Reject an empty explicit target selection and duplicate action identities.

```ts
export interface ISyncPlanOptions {
  autoTranslate: boolean
  exclude?: string[]
  extra?: TSyncExtraPolicy
  include?: string[]
}
```

- [ ] **Step 2: Plan source keys**

For each target in configuration order and each source key in lexical order, ignore filtered-out keys. Emit `keep` for an existing string leaf, `add` with empty target value for a missing path without auto-translation, `translate` for a missing path with auto-translation, and `conflict` for leaf/object path collisions. Never overwrite an existing target leaf.

- [ ] **Step 3: Plan extra target keys**

For filtered target leaves absent from the source, emit `keep/extra_kept`, `keep/extra_reported`, or `remove/extra_removed` according to policy. Ensure a key receives exactly one action.

- [ ] **Step 4: Freeze and adapt the plan**

Freeze every action, its nested filters, the action array, targets, and the plan. Generate translation requests only from `translate` actions as `{from: plan.source, key, sourceText, to: language}` in action order.

- [ ] **Step 5: Verify planner compilation and invariants**

Run `npm run build` and `npm run lint`. Inspect the compiled declarations to confirm readonly public types are emitted and there are no imports from command modules.

### Task 4: Guarded multi-file execution

**Files:**
- Modify: `src/shared/atomic-file.ts`
- Create: `src/shared/sync-executor.ts`

**Interfaces:**
- Produces: optional guarded preconditions for `applyFileTransaction` without changing existing callers.
- Consumes: `ISyncProjectSnapshot`, `ISyncPlan`, optional `ITranslationBatchOutput`.
- Produces: `SyncExecutor.apply(input: ISyncExecutionInput): Promise<string[]>`.

- [ ] **Step 1: Add transaction preconditions**

Extend the transaction API with an optional second argument containing exact expected file states. Preconditions support an expected `Buffer` or expected absence (`null`). Resolve and deduplicate paths, read every current state, and compare with `Buffer.equals` before applying the first mutation. Existing one-argument calls retain their current behavior.

```ts
export interface IFilePrecondition {
  expected: Buffer | null
  file: string
}

export async function applyFileTransaction(
  mutations: IFileMutation[],
  options?: {preconditions?: IFilePrecondition[]},
): Promise<void>
```

- [ ] **Step 2: Resolve executable sync values**

Build a lookup of safe translation results by `(to,key)`. Apply `add`, `remove`, and successful `translate` actions to cloned target dictionaries. `keep`, `skip`, structural conflicts, failed/conflicted/skipped/remaining translations, and dry-run translation outcomes do not mutate dictionaries.

- [ ] **Step 3: Generate one transaction**

Serialize only target dictionaries whose content changed. Generate types once with `generateTypesContent(snapshot.config, snapshot.source.dictionary)`. Include the types mutation once, unless its bytes already match. Add exact preconditions for source, every selected target, and the types file state, then call `applyFileTransaction` once.

- [ ] **Step 4: Preserve all-or-nothing failure behavior**

Reject execution when the plan contains structural conflicts. Let stale preconditions abort before writes. Let `applyFileTransaction` rollback any already applied dictionary or enum mutation on filesystem failure. Return written file paths in target configuration order followed by the types file.

- [ ] **Step 5: Verify compilation**

Run `npm run build` and `npm run lint`. Confirm existing language and translate commands still compile against the backward-compatible transaction signature.

### Task 5: Stable sync reporting

**Files:**
- Create: `src/shared/sync-report.ts`

**Interfaces:**
- Consumes: plan, optional batch result, dry-run/write/confirmation state, written paths.
- Produces: `buildSyncReport(input: ISyncReportInput): ISyncReport`.
- Produces: `formatSyncReport(report: ISyncReport): string[]` for ANSI-free logical lines; command may color human labels after formatting, never JSON.

- [ ] **Step 1: Define action outcome accounting**

Map each planned action and batch outcome to exactly one per-language counter. Successful non-cached and cached translations both count as `translated`; add actions count as `added`; remove and keep are direct. Translation skip/conflict/failure/remaining outcomes replace the translation counter for that action so the summary total equals the action count.

- [ ] **Step 2: Build deterministic JSON**

Return source, ordered targets, extra policy, filters, autoTranslate, dryRun, writeRequested, confirmed, actions, batch details, summary by language, aggregate summary, exitCode, and written files. Order object construction explicitly and never insert Error objects or ANSI strings.

- [ ] **Step 3: Build compact human output**

Emit changed/problem actions followed by one summary line per target and a total line. `extra=keep` may omit individual retained extras; `extra=report` shows them. Always display conflicts, failures, and remaining work.

- [ ] **Step 4: Verify report invariants**

Run `npm run build` and `npm run lint`. Check in code that every action identity is accounted once and throw an internal invariant error if aggregate total differs from `plan.actions.length`.

### Task 6: Replace the label:sync command

**Files:**

**Interfaces:**
- Consumes all services from Tasks 1–5 plus `TranslationService`, `TranslationBatchService`, and `resolveTranslationBatchConfig`.
- Produces the public flags and exit behavior specified by Task 10.

- [ ] **Step 1: Declare the v2 CLI surface**

Set `enableJsonFlag = true`. Add kebab-case flags `dry-run`, `source`, repeatable `to`, repeatable `include`, repeatable `exclude`, `extra` with options, `auto-translate`, `engine`, exclusive `fallback`/`no-fallback`, and `write`. Remove Listr, table, chalk task orchestration, `--noReport`, and `--silent`.

- [ ] **Step 2: Validate all local inputs before network/write**

Read config, reject `--dry-run --write`, validate source/targets through the repository, validate patterns/planning options, resolve `config.batch`, and validate engine/fallback only when auto-translation is requested. Reject engine/fallback flags without `--auto-translate`. In non-TTY, reject a mutating run without `--write`; permit `--dry-run` everywhere.

- [ ] **Step 3: Build plan and optional batch**

Load snapshots once and create the immutable plan. When auto-translation is enabled, pass `syncTranslationRequests(plan)` to `TranslationBatchService.execute` with shared batch config and `dryRun: flags['dry-run']`. Build `TranslationService` with the same cache file and engine/fallback overrides as `ctv translate`; do not instantiate it during dry-run.

- [ ] **Step 4: Coordinate preview, confirmation, and execution**

Never execute on dry-run. With `--write`, execute directly if there are no structural conflicts. In TTY without `--write`, render the preview, prompt once with `confirm`, and execute only on acceptance. JSON mode is non-interactive and therefore requires `--write` for mutation.

- [ ] **Step 5: Render and set exit codes**

Return the report object in JSON mode and print human lines otherwise. Exit 2 for usage/config/read/stale/write errors. Exit 1 for structural or translation conflicts, failed requests, or remaining work. Automatic skip alone and a declined TTY confirmation retain exit 0.
